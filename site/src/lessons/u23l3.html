Tokens on Solana look simple until Token-2022 adds extensions that can tax every transfer, run arbitrary code on each transfer, or let the issuer seize anyone's balance. For a builder integrating tokens, a DEX, a lending market, a wallet, the critical skill is reading what a token can do to its holders and deciding which capabilities you'll accept. This lesson is the Solana token model and the extensions that make integration a security decision, not a formality.

Mints and token accounts

  • A mint account defines a token: its supply, decimals, mint authority (who can create more), and freeze authority (who can freeze holders).
  • Balances live in token accounts, one per (owner, mint). The associated token account (ATA) is the canonical one, derived deterministically from the owner and the mint (a PDA, Unit 23 lesson 1).

The trust signals buyers and integrators check: is the mint authority revoked or held by a program PDA (so no human can print more, as in the launchpad lab), and is there no freeze authority (so no one can freeze your tokens)? These two facts separate a token you can safely hold from one the issuer controls.

Token-2022 extensions

Token-2022 adds optional extensions, and some of them hand the issuer real power over holders:

Integrators inherit the issuer's powers

Here's the design imperative: a DEX, lending market or wallet that accepts a Token-2022 token inherits whatever powers its extensions grant the issuer. A pool that accepts a token with a transfer hook can have its sells blocked (the hook is a honeypot, Unit 20). A lending market that accepts a token with a permanent delegate is lending against collateral the issuer can seize. So integrators must deliberately allowlist which extensions they accept, and refuse tokens whose extensions give the issuer powers incompatible with the integration. "It's a token, we support tokens" is how you accidentally accept a honeypot or seizable collateral. The check is mandatory, not optional.

Build it

Write a TypeScript script that takes any mint address and prints a risk report: the program (Token or Token-2022), supply, decimals, mint and freeze authority, and every extension present, flagging transfer hooks and permanent delegates specifically. Building the risk-report tool is exactly what a responsible integrator needs before listing any token, and writing it teaches you to read a token's full capability set from on-chain data, which is the Solana version of "read the contract before you trust it" and the defence against the honeypot and seizable-collateral risks above.

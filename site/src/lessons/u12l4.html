Bridges hold more value in one place than almost anything else in crypto, and they've lost more of it than anything else. The striking thing about the history is how little of it involved broken cryptography. Almost every major bridge loss came from compromised keys, weak configurations, or verification bugs, the mundane failures, not the exotic ones. This lesson walks six incidents, each teaching a specific, reusable design rule.

Six incidents

Bridge hacks and the rule each teaches

Multichain, Jul 2023, ~$126M"MPC" keys effectively controlled by one personverify decentralisation claims
KelpDAO rsETH, Apr 2026, ~$292Ma single-DVN config; the attacker poisoned the DVN's RPC nodes and DDoS'd the clean ones so it signed a forgerynever run single-verifier bridges; monitor supply

Reading the table

Line them up and the pattern is undeniable. Ronin, Harmony and Multichain were key compromises: the signers' keys were stolen or were never really decentralised. Wormhole and Nomad were verification bugs: the contract accepted something it shouldn't have (a spoofed account, a zero root). KelpDAO was a configuration failure: a single verifier that was then tricked. None was a break in the underlying cryptography. The hash functions and signature schemes held; the systems around them didn't.

The Nomad lesson in particular

Nomad is worth dwelling on because it shows how a tiny mistake becomes a total loss. A routine upgrade initialised the trusted Merkle root to zero. With a zero root, every message proved valid, so anyone could withdraw anything by submitting a message that "proved" against the zero root. And because the exploit was so simple, a crowd of people copy-pasted it, each draining what they could, in one of the first "decentralised" bank robberies. The rule, test upgrades and initialisers adversarially (Unit 5's uninitialised-implementation class), is specific, but the meta-lesson is that a single wrong value in an upgrade drained $190M.

Contagion

Bridged collateral spreads the damage

KelpDAO showed a newer dimension: the stolen rsETH was posted as collateral on Aave to borrow WETH (Unit 7). So a bridge failure became a lending-market problem within hours. Aave, SparkLend and Fluid froze rsETH; Ethena, Yearn and Pendle paused related products. The bridge's $292M loss radiated into every protocol that had accepted bridged rsETH as collateral. This is the contagion that makes bridge risk systemic: bridged assets flow into lending, and a counterfeit at the bridge becomes bad debt everywhere downstream.

The lessons, consolidated

  • Keys and configuration, not cryptography, cause the losses. Spend your security budget on key management, signer independence and config review, not on exotic crypto.
  • Contagion amplifies. Bridged collateral in lending markets spreads the damage far beyond the bridge. Monitor where your bridged assets end up.
  • Rate limits would have capped almost every one of these. A cap on mints per time window turns a $600M drain into a bounded one and buys time to pause. It is the single highest-leverage bridge safety feature, and most of these bridges didn't have it.

Build it

Reproduce the Nomad bug in Foundry: a minimal replica with a confirmedAt[root] mapping, an upgrade that initialises the trusted root to zero, and an exploit test that drains it by proving against the zero root, run against your own local contract. Then add the test that would have caught it before deployment (an assertion that the root is non-zero after initialisation). Reproducing a real $190M bug in a few lines, and then writing the one-line check that prevents it, is the most efficient security lesson there is.
